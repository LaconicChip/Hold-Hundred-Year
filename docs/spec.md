## 1. 项目概述与目标

基于 Spring Boot 的微型虚拟股市模拟游戏。后端定时任务驱动行情、WebSocket 实时推送、数据库事务与锁保障交易一致性，用于深度练习 Spring Boot 企业级技术栈。

**核心模式：账户隔离的单机存档游戏。** 每个注册账户拥有一个完全独立的游戏世界：独立的交易日进度、行情序列、突发事件、主力剧本。玩家扮演资金量不影响市场的散户，按当前价与系统成交；除涨跌停板与停牌限制外均可成交。各账户之间互不可见、互不影响。

**博弈主题：与"主力"斗智斗勇。** 行情不只是随机游走——系统会以 NPC 庄家身份按现实 A 股套路运行操盘剧本（洗盘吸筹、拉高出货、尾盘偷袭、天地板），并配套释放真假难辨的消息（假利空吓人割肉、假利好诱人接盘）。消息有来源分级与"传闻→证实/辟谣"生命周期，玩家靠信息辨别力与心态获利。

练手目标覆盖：Spring Security + JWT 认证、Spring WebSocket（STOMP）点对点推送、定时调度与线程隔离、MyBatis-Plus、MySQL 悲观锁（SELECT ... FOR UPDATE）与乐观锁（version）、高并发下资金安全验证。

## 2. 技术栈

- **后端**：Spring Boot 4.1.1、Java 17、MyBatis-Plus、MySQL 8（InnoDB）、Spring WebSocket（STOMP 子协议）、Spring Security + JWT（jjwt）、Lombok、spring-boot-starter-validation、springdoc-openapi（接口文档）。

- **前端**：Vue 3 + Vite + Element Plus + Pinia + Vue Router + axios + ECharts（分时图）+ @stomp/stompjs（WebSocket 客户端）。

- **形态**：前后端两个独立工程；后端仅提供 REST + WebSocket。
- **存储与分发形态**：开发/局域网档用 MySQL 8（并发锁与事务是练习目标）；"解压即玩"绿色包用内嵌 H2 文件库（`portable` profile，`schema.sql` 仍是唯一权威，H2 侧运行时翻译方言），由 jpackage 捆一个 JRE 进去，玩家电脑零依赖。两种形态共用同一套 SQL、实体与引擎代码，只在数据源一处分支。密码使用 BCrypt 加密。

- **便携版是彻底的单机游戏，没有账号系统**（`portable` profile 独有）：一台机器 = 一个人 = 一份存档，入口只有两个动作——**继续游戏**与**创建新游戏**（已有存档时后者先弹红色警告，写清"第几日、净资产多少、清空后不可恢复"，二次确认才动手）。实现上仍复用 `sys_user` 一行（整套数据以 user\_id 为键，引擎不关心人是怎么进来的），用户名固定 `单机玩家`、密码是随机 BCrypt 串——**任何人都无法用密码登录他**，进入只靠 `/api/auth/local/resume` 发的免密令牌。账号那套（注册/登录/多人排行榜）代码原样保留在默认档，将来上线部署时不开 portable 档就自动复活，两个版本共用一份引擎；`LocalEntryIsPortableOnlyTest` 钉住"免密入口只能存在于 portable 档"。

- **线程模型**：Tomcat 线程处理 HTTP 请求；行情/剧本/事件/时钟推进运行在独立调度线程池，与 HTTP 线程隔离。

## 3. 游戏时间与市场状态机

时间常量（可配置）：

| 参数     | 值                             |
| ------ | ----------------------------- |
| 行情跳价间隔 | 1 秒 / 跳                       |
| 上午盘    | 45 跳（45 秒）                   |
| 午休休市   | 10 秒                          |
| 下午盘    | 45 跳（45 秒）                   |
| 一个交易日  | 现实 1 分 40 秒，共 90 个价格点          |
| 游戏年长度  | 24 个交易日 / 年（1 月 ≈ 2 个游戏日）     |
| 游戏总长度  | 3 个游戏年，共 72 个交易日；满 72 天正常收官    |
| 一局总时长  | 约 2 小时（72 × 100 秒），另可用"快进"再压缩 |

> **一局一个档案**（`GameMode`，存 `user_game_state.game_mode`，建局时选定、整局不可改）：
>
> > 模式在**开每一局时**选（大盘页开局前 / 终局页"再来一局"），注册时不绑定。
>
> | 档案 | 年长 | 跳间隔 | 午休 | 一天 | 一局 | 涨跌停 | ST |
> | --- | --- | --- | --- | --- | --- | --- | --- |
> | 标准 STANDARD | 24 交易日 | 1000ms | 10 秒 | 100 秒 | 72 天 ≈ 2 小时 | ±10% | ±5% |
> | 快速 QUICK | 12 交易日 | 500ms | 5 秒 | 50 秒 | 36 天 ≈ 30 分钟 | ±20% | ±10% |
>
> 两种档案**跳数都是 45+45=90**，11 个纪元、全部剧本日类型、封板/炸板、T+1、停牌核查、ST 戴帽、
> 除权除息、打新 D+2/D+4、融资追保/强平一个都不减；快速模式只是把时间轴压密、把单日振幅放大。
> 纪元最短长度随档案变化（标准 3 天、快速 2 天）：一年 12 天要装 4 个纪元，3 天下限没有余量。黑7月崩盘日的撒点窗口也随档案变化（标准 = 纪元 10 前半段，快速 = 整个纪元，见 §4.4）：短局的名场面靠"更密"而不是"更少"。

> 跳数（45+45=90）与每跳的波动标定是**不动量**：改节奏只改"每跳多少毫秒"与"一年多少交易日"，
> 所以行情形态、封板时长、日内 U 型完全不变，随机序列仍按跳消费、同种子同结果。

市场状态机（每个账户独立）：

```
NOT_STARTED（第 1 天待开盘）
   └─(玩家手动"开始第 1 天")→ MORNING_OPEN
MORNING_OPEN（上午盘 45 跳，行情跳动，可交易）
   ├─ 45 跳结束 → LUNCH_BREAK
   └─ 熔断触发（仅第 2 年纪元 5，指数日内 ≤ -7%）→ SETTLING（当日提前收盘）
LUNCH_BREAK（午休 10 秒，行情停跳，不可下单；发布午间消息）
   └─ 10 秒结束 → AFTERNOON_OPEN（应用午间消息造成的下午开盘跳空）
AFTERNOON_OPEN（下午盘 45 跳，行情跳动，可交易）
   └─ 45 跳结束 → SETTLING
SETTLING（自动收盘结算，瞬间完成）
   ├─ 爆仓（资不抵债）→ BANKRUPT（游戏提前结束）
   ├─ 第 72 天结算完成 → FINISHED（三年期满，正常收官）
   └─ 其他 → CLOSED
CLOSED（已收盘，不可交易；发布盘后消息、结算评价、称号判定、融资计息与担保检查）
   └─(玩家手动"开始下一交易日")→ MORNING_OPEN（current_day + 1，应用隔夜跳空、纪元切换）
BANKRUPT / FINISHED（终局：冻结一切操作，展示结局结算页）
```

关键规则：

- **手动开盘**：`NOT_STARTED` 与 `CLOSED` 状态下，玩家点击"开始 / 下一交易日"才推进；服务端校验状态，重复点击幂等无效。不存在自动跨天。

- **离线暂停**：游戏时间仅在该账户 WebSocket 在线时推进。断开连接时行情停跳、午休倒计时暂停，状态持久化；重连后从断点继续。

- **收盘结算（SETTLING）自动执行**：

  1. 全部股票当前价快照落库；
  2. `prev_close`（次日涨跌停基准）= 当日收盘价；
  3. T+1 解冻：所有持仓 `available_shares = shares`；
  4. 连板统计：当日收涨停的股票 `limit_up_streak + 1`，否则归零；触发停牌核查判定（见 §7.4）；
  5. 融资计息：负债按日利率（年化 8% ÷ 本局年交易日数）计提；紧接着高利贷计息与到期清算（见 §6.6）；随后计算担保比例（总资产 ÷ 融资负债）：< 140% 推送追保警告；< 120% 强制平仓（按收盘价依次卖出持仓还债，见 §6.4）；两种债合计后仍资不抵债 → 状态转 **BANKRUPT**（爆仓结局）；
  6. 日收益评价：玩家当日收益率 vs 百年指数当日涨跌幅，推送评价；
  7. 称号与挑战徽章检测解锁（§7.7）、资产段位评定（tier 升降级）；
  8. 写入 user\_daily\_snapshot（现金/市值/负债/净资产/日收益率/指数点位/营业部 NPC 资产）；更新当日排行榜；
  9. 打新结算（中签缴款/上市连板结算，见 §6.5）、除权除息预排（次日开盘前处理）；
  10. 盘后消息抽取（含隔夜跳空幅度，写入 `gap_pct` 待次日开盘应用）；
  11. 重置次日 open/high/low；
  12. 若为第 `GameMode.totalDays()` 个交易日（标准 72 / 快速 36） → 状态转 **FINISHED**（三年期满收官，生成三年总成绩单）；否则转 CLOSED，推送结算通知。

- **纪元切换**：开盘时按 `current_day` 查本局纪元时间表（见 §4.3），若进入新纪元，推送一条权威/媒体风格的"纪元叙事"消息（如"杠杆牛启动""贸易战打响""黑7月来临"）。

- **熔断提前收盘**：仅纪元 5（熔断开局）期间生效，上午盘指数自昨收跌幅触及 -7% 的当跳 → 立即进入 SETTLING（跳过午休与下午盘），推送交易所权威公告"触发熔断，全天交易结束"。

- **跳过当日（快进）**：只对"今天还没收盘"的日子开放——开盘/午休状态下可"跳过当日"（前端二次确认）。收盘后**不再提供**"跳过下一交易日"入口：那等于把玩家从没看过的一整天凭空过掉（25 号收盘 → 直接 26 号已收盘 → 27 号开始），毫无参与感；要连续快进就"开始下一交易日"再"跳过当日"，每一天都被明确地跳过一次。服务端 `POST /api/market/skip` 仍保留从 NOT\_STARTED/CLOSED 快进的能力（自动化测试驱动多日推进用），只是 UI 不暴露。服务端对该账户世界执行**完整快进**：从当前时刻起的剩余行情逐跳快速模拟（毫秒级跑完，不推 WebSocket），主力剧本、突发事件、传闻/辟谣、午休/盘后消息照常触发并落库，随后走正常 SETTLING 结算，返回**收盘总结页**数据（见 §12.7）。快进后果真实：T+1 解冻、连板统计、停牌判定、融资计息、追保/强平/爆仓全部照常；熔断日快进触发熔断即提前收盘；本局收官日快进结算后进入 FINISHED。终局态（BANKRUPT/FINISHED）不可跳过。

- **世界锁**：每个账户世界一把 ReentrantLock，调度线程的正常逐跳推进与 HTTP 线程的快进/开盘/结算互斥；调度器拿不到锁（tryLock 失败）则跳过本轮 tick。

### 4.2 百年指数（大盘基准）

- "百年指数"以 24 只股票等权合成，基期 1000 点；每跳按全部非停牌股票的平均涨跌幅更新。

- 指数随行情一起广播；前端大盘页顶部展示指数点位与涨跌幅，分时图可叠加玩家资产曲线对比。

- 每日结算记录指数收盘点位，用于"跑赢/跑输大盘"评价。

### 4.3 大行情纪元：三年编年体剧本（宏观系统）

游戏不是无限随机波动，而是一场浓缩 2014H2–2026.8 真实 A 股历史的**编年体大剧**：11 个纪元**按顺序全部发生**（硬保证），但每局的起止时间与强度都有随机性。

**驱动机制**：每个纪元给百年指数一个**市场漂移** μ\_mkt（每跳），给各板块一个**板块系数**（强 = 额外正漂移、弱 = 额外负漂移、中 = 跟随市场）。个股价格 = 随机游走 + μ\_mkt + 板块系数漂移 + 个股剧本/事件漂移。时间换算：游戏年 Y、年中第 D 个交易日（D=1..24），总 `current_day = (Y-1)×24 + D`。

**两层随机（反公式化）**：

1. **存档层（注册时掷一次，持久化到** **`user_era`** **/** **`user_script_day`** **表，重启不变、每局不同）**：

   - **纪元时间表抖动**：纪元边界在基准日上 ±1~~3 天随机（同年纪元不重叠、不留空档、每个纪元最短 2~3 天（随档案），**纪元 3 例外：不得短于 4 天**（要装下"≥2 天千股跌停 → 救市 → 次日涨停"）、纪元不跨年）。抖动规则（分界基准写在"36 交易日/年"的基准日历里，掷点时按当前年长等比映射，因此改档案年长不需要重排纪元）：年 1 三个分界基准 D10.5/D20.5/D28.5 分别 ±3/±2/±2 天；年 2 纪元 5 固定从第 1 天开始、长度 3\~5 天（长度是"天"，不随年长缩放），白马/贸易战分界基准 D20 ±3；年 3 分界基准 D12/D24/D32 分别 ±2/±2/±1 天；掷完按顺序裁剪保证每段最短 3 天。

   - **纪元强度**：每个纪元的 μ\_mkt 与板块系数在区间内随机取值（同样是疯牛，可能慢牛也可能垂直拉升；黑7月科技股崩多深每局不同）。

   - **剧本日排期**：特殊剧本日（§4.4）在所属纪元内随机落点并持久化。
2. **运行层（每天/每跳随机）**：

   - **波动率体制**：每日 σ 分平静/正常/疯狂三档，且波动聚集（当日体制与前日相关，疯狂日倾向连续，模拟恐慌蔓延）；

   - **反向意外日**：任何纪元每天约 8% 概率出现反向行情（熊市暴力反弹、牛市闪跌洗盘）；

### 4.4 特殊剧本日（历史名场面，保证发生、时点抖动）

剧本日在注册排期时一次性掷出并持久化于 `user_script_day`：**每局保证发生**，但具体游戏日在所属纪元内按下列规则随机，封死比例、目标股等参数亦随机：

- **千股涨停日**：纪元 2 内 1–2 次（随机日）+ 救市次日固定 1 次。开盘 85%\~95% 的股票直接封涨停（买单买不进，幸存股随机），还原 2015 疯牛与救市行情。

## 5. 行情引擎（内存权威 + 快照落库）

- **开局前历史 K**：`stock_daily_bar` 除本局结算日（game_day ≥ 1）外，注册播种时还为每只票写入 20 根`game_day 0..-19` 的历史 K（前史走势按板块档案派生，见 `game/constants/PreHistoryDefs`，最新一根收盘钉在发行价，与本局昨收无缝衔接）。前史**只供日K图展示**：不参与昨收、指数基期、结算与涨跌停判定；掷骰用独立 salt（`"prehistory"+stockId`），不影响既有随机流。

- **内存权威**：在线用户的报价保存在内存，键为 `(userId, stockId)`。每只股票一个 `Quote` 对象：currentPrice、open、high、low、prevClose、limitUp、limitDown、limitUpStreak（连板数）、halted（停牌标志）、sealed（封板状态 NONE/UP/DOWN）、sealTicksLeft（封板剩余跳数）、garchK（GARCH-lite 自适应系数，初值 1）、dayAvg（当日成交均价，用于回归与日收益），以及当日分时环形缓冲（容量 ≥90 点）。

- **每跳推进**（仅 MORNING\_OPEN / AFTERNOON 状态、且用户在线）。波动模型采用**三层因子 + 四个机制**（模拟真实金融市场的波动聚集、肥尾、日内 U 型、涨跌停磁吸）：

  **三层因子（每跳生成）**：

  1. 市场因子：`r_mkt = μ_era + σ_mkt · Z_mkt`。μ\_era 为当前纪元（查本局 `user_era`）的市场漂移，σ\_mkt 为市场基准波动；反向意外日 μ 取反；
  2. 板块因子：`r_sec = σ_sec · Z_sec`，同板块股票共享同一个 Z\_sec（板块联动）；
  3. 个股收益：`r_i = β_i · r_mkt + s_i · r_sec + σ_i · Z_i + 跳跃_i + 剧本/事件冲击_i + 磁吸项_i − κ·(current − 当日均价)/当日均价`。最后一项是**日内均值回归**（κ = `OU_KAPPA` = 0.035）：纯随机游走只会越走越远，分时图像一条斜线；往当日均价回拉才有真实盘面"围绕均价来回抖"的手感，同时把日收益方差压住。该项不消费随机数，同种子仍同结果。β\_i 存于 `stock_info.beta`（券商/科技妖股 1.3~~1.6，白酒/银行/煤炭 0.6~~0.9，其余 0.9\~1.3）；加权 β 标定 ≈1，使指数收益 ≈ r\_mkt。

  **四个机制**：

  - **GARCH-lite 波动聚集**：自适应系数 `k_t = 0.85·k_{t-1} + 0.15·min(|r_{t-1}| / σ_条件, 1.8)²`（k 初始 1），大阳线/大阴线后波动持续放大、平静后收敛。**2026-10-20 改了两处**：比率取<b>平方</b>、分母取<b>当前条件 σ</b>（含本股特质倍数、日内包络与 k 本身）。旧版用线性比率 + 基准 σ 做分母，k 的不动点是"k = 0.8·k"这类退化解，实测被压到 0.05~0.4，个股波动倍数被整段抵消；改成平方后不动点稳定在 k ≈ 1，k 只反映"这一跳是不是特别大"。

  - **肥尾跳跃**：每只股票每跳约 0.7% 概率叠加跳跃 `J = (5~8)·σ_i · Z_jump`（方向随机；事件/剧本/剧本日触发的跳跃方向由脚本指定）。跳跃幅度跟**本股自己的 σ** 走（不是全局基准），所以银行跳得轻、妖股跳得重。旧值 4% 等于每股每天期望 3.6 次跳跃，跳跃从"事件"退化成背景噪声，见下方"波动标定"；

  - **日内波动包络（2026-10-20 改，两层）**：① **全市场共性 U 型**（1.12 → 1.02 → 1.00 → 1.08）只作用于市场因子与板块因子，保住"开盘与尾盘略活跃"这个 A 股共性，幅度刻意温和（旧版 1.6/0.8/1.4 会让玩家看到"开局动一下、中间几乎平盘、收盘再动一下"）；② **个股相位包络**（振幅 ±22%，以 90 跳为周期）只作用于个股特质项，相位由每只票的 `volPhase` 给定、24 只票互不相同——旧版 24 只票共用一条曲线，于是"固定时间集体暴动"（玩家原话："每只股的波动情况很相似，都会在固定时间突然大涨或者大跌一轮"）。下午开盘首跳叠加午间消息跳跃；

  - **涨跌停磁吸与封板**：日内涨跌幅 ≥9%（`MAGNET_TRIGGER`）后开始吸，且**吸力随贴近度线性增强**（触发线处为 0、贴到板上是满档 ±0.12%/跳）——旧版是"一过线就给恒定漂移"，等于"只要摸到 6.5% 就必然收在涨停板上"，日 σ 抬到 5% 之后会让每天 4 只票上板；随后逐跳掷骰封板；封板成功后价格钉死涨停/跌停（**涨停封死买不进、跌停封死卖不出**），持续 5\~30 跳后掷骰**炸板**（封单被吃，瞬间反向 2%\~4% 冲击，天地板/地天板由此产生）或封死至收盘（收板）。连板股（limit\_up\_streak ≥2）磁吸强度与封板概率递增（妖股越妖）。封板/炸板状态保存在内存 Quote（sealed: NONE/UP/DOWN + 剩余封板跳数），收盘重置；一字板（隔夜 |gap|≥10%）开盘即封死。

  **每跳处理顺序**：

  1. 生成 r\_mkt（含纪元 μ、当日波动率体制 CALM/NORMAL/WILD 系数 0.6/1.0/2.0、U 型系数）；
  2. 生成各板块 r\_sec 与各股 Z\_i、跳跃、GARCH 系数；
  3. 特殊剧本日（查 `user_script_day`）强制行为优先（千股涨停/跌停按封死比例锁定、制裁闪崩、黑7月崩盘）；
  4. 主力剧本（§7.1）与事件冲击（§7.3 七种反应模式）施加定向漂移；政策面事件（§7.4）施加全市场同向偏移；
  5. 磁吸判定与封板/炸板状态机更新；

**波动标定（2026-10-16 重标定，2026-10-19 压平日内 U 型，2026-10-20 引擎大改，验收见 `VolatilityDistributionTest`）**：
  <p><b>2026-10-16 那一轮</b>把绝对量级整体收敛了一档：改之前真的跑完整局量出来是<b>日收益标准差 8.0%、55% 的股票天收在涨跌停板上</b>（真实 A 股约 2% 与 1%~2%），玩家的实际观感就是"不是涨停就是跌停、平稳行情也这样"，而分时图是一条 45° 斜线加一段水平（封板）。四个来源：每跳跳跃概率 4%（≈每股每天 3.6 次跳）、GARCH 上限 4.0（一次大跳后 σ 翻四倍，直奔板）、纪元漂移的绝对值（最热板块每跳 +0.30% = 单日 +27%）、磁吸在 +6.5% 就触发（离板还剩 3.5%，而漂移每跳 0.15%，等于过线必上板）。标定后跨种子实测：<b>有机行情 σ 3.0~3.2%、有机贴板日约 4~5%、±6% 以上有机日约 6.5~7.2%</b>（含剧本日的整体贴板约 10.3~11.7%——千股涨停那几天仍然必须满屏，那是名场面）。纪元档案里的 μ 与板块系数改读为<b>相对强度</b>，落地统一乘 `ERA_DRIFT_SCALE`。
  <p><b>2026-10-19</b>又发现旧的 U 型曲线（开盘 1.6 / 盘中 0.8 / 尾盘 1.4）把波动挤到首尾，玩家看到的是"开局动一下 → 一路几乎平盘 → 收盘再动一下"；压成温和 U 型（1.25 / 0.95 / 1.15），单跳 σ 微调到 0.0016。
  <p><b>2026-10-20 引擎大改</b>（用户反馈"波动太小"+"每只股都很相似，都会在固定时间突然大涨或大跌一轮"，明确选了"够刺激"档）：把"波动量级"与"个股差异"两件事分开处理。
  <ul>
    <li><b>量级</b>：单跳基准 σ 0.0016 → 0.0038，日 σ 抬到 <b>4.7~5.0%</b>（用户选的"够刺激"档是 4.5~5.5%）。跳跃幅度改为跟本股自己的 σ 走（5~8 倍），跳跃概率 0.5% → 0.7%。</li>

    <li><b>顺带修掉两个自伤机制</b>：GARCH 的比率改平方、分母改当前条件 σ（旧公式的不动点会把 k 压到 0.05，个股波动倍数被整段抵消）；磁吸改成按贴近度增强（旧版"一过线就给恒定漂移"＝"只要摸到线就必然收在板上"）。</li>

  跨种子实测（固定世界种子，三局平均）：<b>有机 σ 4.7~5.0%、有机贴板 11%~12%（每天约 2.8 只票上板）、±6% 以上 23%</b>；<b>个股日 σ 从 3.2% 到 7.4%（离散比 2.3 倍）、两只票的日内轨迹相关从 0.33 降到 0.11（去掉大盘因子后残差 0.12 → 0.00）、日内最大一段变动的发生时段从"38% 挤在开盘"变成均匀分布</b>——也就是玩家说的"固定时间集体暴动"没有了。
  6. 停牌股票跳过（价格冻结）；已封板股票价格钉死、不参与游走；
  7. 价格夹逼在 `[跌停价, 涨停价]`，四舍五入保留 2 位小数；轻微向当日均价回归（防单股脱锚，跨日趋势由纪元漂移提供）；

  **波动标定**（90 跳/天）：有机日个股日波动 **4.7%\~5.0%**（按 `volMult` 分化：死水票 3.2%、疯票 7.4%）、指数 1.2%\~2%；疯狂日（WILD 体制）个股再翻一倍；σ\_i 基准 ≈ 0.38%/跳（个股，再乘 `volMult` 0.55\~1.70）、σ\_mkt ≈ 0.13%/跳（指数）、σ\_sec ≈ 0.20%/跳（板块）。极端行情（千股跌停/涨停/熔断）由剧本日强制行为接管，不依赖随机。

- **PriceShock 冲击队列（多冲击源统一架构）**：纪元漂移、板块因子、主力剧本、事件七种反应模式（§7.3）、剧本日、磁吸等所有"定向冲击"不直接改价，而是生成 `PriceShock`（目标 stockId/SECTOR/MARKET、总幅度、剩余跳数、衰减曲线：一次性/线性/指数、方向）放入内存队列；每跳引擎先跑三层因子随机游走，再统一消费队列内全部活跃 shock 叠加到收益上，到期移除。"脉冲回落""延迟发酵""买传闻卖事实"等反应模式 = 不同衰减曲线的 shock 组合，避免散落的 if-else。shock 队列为内存态，重启清空（事件已持久化于 game\_event，恢复时按当日未完结事件重建关键 shock）。

- **世界种子**：注册播种时掷一个 `world_seed`（long）存入 user\_game\_state；该世界全部随机数（纪元排期、剧本日、波动、事件抽取、打新摇号、NPC 收益）均来自基于此种子的 Random 实例。效果：测试可复现（同种子同价同消息同事件）、重开一局天然不同；终局页展示本局种子号。

- **推进逻辑统一**：单跳推进抽为 `WorldTickService.tickOne(userId)` 纯逻辑（行情→shock 消费→封板机→指数→事件掷骰→消息），调度器按各账户本局档案的跳间隔（标准 1000ms / 快速 500ms）调用一次、快进在持锁循环内连续调用；两者共用同一代码路径，保证快进与正常推进结果一致。

- **调度方式**：单线程 ScheduledExecutorService 每 100ms 心跳扫描"在线且开盘中"的用户会话，到本局跳间隔才推进，顺序逐用户；推进前 `tryLock` 该账户世界锁，失败则跳过本轮（与快进/开盘 HTTP 请求互斥，见 §3）。

- **快进推进**：`POST /api/market/skip` 持有世界锁，在同一循环内连续跑完当前时刻至收盘的全部跳数（含午休消息、剧本日、熔断判定），随后直接执行收盘结算流程（§3），返回收盘总结 DTO（§12.7）。快进期间所有消息/事件正常落库，仅省略 WebSocket 推送与 3 秒等待。

- **快照落库**：每 5 跳及收盘时，批量 UPDATE `user_stock_state`，使用 MyBatis-Plus `@Version` 乐观锁，冲突重试至多 3 次；同时持久化 `user_game_state.tick_index` 用于断点恢复。

- **交易读价**：交易服务直接读内存现价，无数据库 I/O；内存读使用 volatile/CAS 保证可见性。

- **重启恢复**：内存行情从 `user_stock_state` 最近快照重建（Random 从 world\_seed + current\_day + tick\_index 重放定位，保证推进序列可复现）；主力剧本/PriceShock 队列内存态重建（当日未完结事件按 game\_event 重建关键 shock，否则中断后随机新剧本）；封板状态按当前价位重新判定磁吸（sealed/garchK 重置）；当日分时环形缓冲以快照价重新累积（属可接受取舍）。

## 6. 交易规则与资产

### 6.1 交易规则

- **整手交易**：买卖数量必须为 100 的整数倍。

- **涨跌停与封板**：普通股涨停价 = round(prev\_close × 1.10, 2)、跌停价 = round(prev\_close × 0.90, 2)；ST 股（is\_st=true）幅度收窄为 ±5%（见 §6.5）。现价 = 涨停价时拒买（封板提示"涨停封死，买单排不上"）、现价 = 跌停价时拒卖（"跌停封死，卖不出去"）；反方向不受限（涨停可卖、跌停可买）。封板由磁吸状态机决定（§5），**炸板后价格离开涨停/跌停即可成交**；一字板（开盘即封）首跳起锁定。

- **T+1**：买入当日增加 `shares` 但不增加 `available_shares`；收盘结算解冻后才可卖出。

- **交易时段**：仅 MORNING\_OPEN / AFTERNOON\_OPEN 可下单；午休、收盘、未开盘状态拒单。

- **停牌核查**：`halted = true` 的股票不可买卖（提示"该股票正在停牌核查中"），行情冻结、持仓保留。

- **成交价**：下单瞬间的内存现价。玩家资金量不影响市场，无库存概念，不撮合。

### 6.2 费用与资金

- 新账户初始资金：100,000.00 元。

- 佣金：双边收取，`max(成交金额 × 0.0003, 5)` 元。

- 印花税：仅卖出收取，`成交金额 × 0.001`。

- 买入总支出 = 成交金额 + 佣金；卖出净收入 = 成交金额 − 佣金 − 印花税。

- 成本均价（买入后）：`new_avg_cost = (old_shares × old_avg + 成交金额 + 佣金) / new_shares`；卖出不改变 avg\_cost。

- 资产看板：可用现金 = balance；股票市值 = Σ(currentPrice × shares)（停牌股按停牌前价格）；总资产 = 现金 + 市值；**净资产 = 总资产 − 负债（融资借款）**；总盈亏 = 净资产 − 100,000；浮动盈亏 = Σ((currentPrice − avg\_cost) × shares)。

### 6.3 下单校验链（按顺序短路）

1. 已认证；
2. 市场处于开盘状态（否则"休市中，无法下单"）；
3. 数量为 100 的正整数倍；
4. 股票存在且未停牌；
5. 买入：currentPrice < limitUp（涨停拒买）；卖出：currentPrice > limitDown（跌停拒卖）；
6. 买入：balance ≥ 成交金额 + 佣金；卖出：available\_shares ≥ 委托数量；
7. 执行事务。

### 6.4 融资贷款与爆仓

- **借款**：可随时向券商融资，**累计负债（融资 + 高利贷）不超过净资产**（1:1 杠杆）；借款即时到账 balance，debt 增加。可借额度 = 现金 + 市值 −（融资债 + 高利贷）× 2，公式只在 `MarginService.marginBorrowableOf` 一处，借款校验与 `/api/me/assets.borrowable` 共用。

- **还款**：可随时用现金归还负债（金额 ≤ min(现金, 负债)），不计违约金。

- **计息**：每个交易日收盘结算时，`debt ×= (1 + 日利率)`，日利率 = 年化 8% ÷ 本局年交易日数（标准 24、快速 12，见 §2 档案）——年化不随模式变，短局一天计提更多。

- **担保比例** = 总资产 ÷ 负债（负债为 0 时不检查）。收盘结算时检查：

  - < 140%：推送"追保通知"（警告，不操作）；

  - < 120%：**强制平仓**——按当日收盘价，从市值最大的持仓开始逐只卖出（正常计佣金/印花税），所得现金优先归还负债，直到担保比例 ≥ 130% 或持仓清空；推送强平通知；

  - 强平后若净资产 ≤ 0（资不抵债）→ **爆仓**：状态转 BANKRUPT，游戏提前结束，展示"天台结局"结算页（负债、亏损、存活天数）。净资产按**融资 + 高利贷合计**算：券商只平自己的仓，但你欠放高利贷的钱一样能把你打死。

- 融资买入的标的与普通买入一致（不限制标的、不做融券做空）。

### 6.5 A 股特色机制

- **ST 戴帽/摘帽**：个股触发重大利空事件（立案调查、连续巨亏、审计无法表示意见）后戴帽：`user_stock_state.is_st = true`，前端股名加"ST"前缀，**涨跌停幅度由 10% 收窄为 5%**（涨停价 = prev\_close × 1.05、跌停价 × 0.95）；戴帽通常伴随连续跌停。戴帽后 15\~25 个交易日内，若公司发布"扭亏/重组进展"利好则摘帽（is\_st = false，恢复 10%），摘帽日常有涨停行情（"摘帽行情"）。每只股票每局至多戴帽 1 次。

- **高送转/分红除权**（事件触发，开盘前处理）：

  - 高送转（如 10 转 10）：持仓 shares 与 available\_shares 同比例放大、avg\_cost 同比例缩小、prev\_close 与现价同比例除权（市值不变）；消息面配合"高送转预案"炒作，除权前常有抢权行情、除权后可能"填权"（上涨）或"贴权"（下跌）。

  - 现金分红（每股派 X 元）：balance 增加 `shares × X`（扣税简化忽略），prev\_close 与现价除息 −X；分红日推送到账通知。

  - 除权除息在开盘首跳前一次性处理完毕，当日涨跌停基准按除权后价格计算。

  - **折算范围是"当日全部口径"**：昨收、当日开盘/最高/最低/现价、当日均价、分时缓冲一起折算，并同步双写 `user_stock_state` 的对应列（结算落日K读的就是这几列）。只折昨收与现价的话，除权当日那根日K会留着除权前的最高价去配除权后的收盘价，图上凭空多出一根"腰斩大阴线"，而 tooltip 显示的是按除权后基准算出的真实日内涨跌幅——图和数字各说各话。

  - **日K图按"前复权"绘制**（`GET /api/stocks/{id}/kline`，见 §10）：`stock_daily_bar` 存的永远是**当日真实成交价**（历史价不被后来的公司行动改写，所以表里不加复权列），下发时以最新一根收盘价为锚、沿 `change_pct` 往回链式还原连续序列，再按因子同乘每根的 OHLC。`change_pct` 是收益率、天然对拆股免疫，因此它就是唯一的还原依据。图上标注「前复权」。

- **新股申购（打新）**：每年 2\~3 次，按纪元排期（与剧本日同批在注册时掷出，存 user\_script\_day，script\_type = IPO）。**收官前 4 天不再排申购日**：申购后还要 D+2 上市、D+4 结算，卡在尾巴上会让玩家点完申购就终局、钱冻在一只既没上市也没结算的新股里（短局尤其容易撞上）：

  1. 申购日开盘推送"XX 新股今日申购，发行价 Y 元"，弹窗/通知提供"顶格申购"按钮（`POST /api/ipo/subscribe {ipoId}`，当日有效，无需冻结资金）；
  2. T+2（2 个游戏日后）开盘公布中签：游戏化中签率 20%\~35%（牛市偏低、熊市偏高），未中签推送"感谢参与"，中签则按发行价缴款（1000 股，balance 不足视为放弃）；
  3. 中签新股**不加入 24 只行情列表**：上市日按纪元掷连板数（疯牛纪元 6~~12 板、结构牛 3~~6 板、熊市 0\~2 板或首日破发 −10%），开板日按 `发行价 × 1.1^N`（破发则 ×0.9）自动卖出结算，现金直接入 balance 并推送"XX 新股开板卖出，中签盈利 Z 元"。

  - 纯事件结算，零行情与持仓复杂度；玩家体验"中签如中彩票"与"熊市打新也破发"。

### 6.6 高利贷（场外配资，风险自担）

营业部的融资被 1:1 杠杆与"强平救回"锁死——2 倍仓位碰上一天 20% 的跌停也只是伤筋动骨，**天台上其实排不到人**。所以另开一条自愿的自毁通道：钱从场外借，利息按天涨，到期必须还。

- **额度**：可借 = 净资产 × 5（`SHARK_LIMIT_RATIO`）− 已借未清余额。借满就是 6 倍仓位：**单个交易日跌 16.7% 就资不抵债**（快速模式一个跌停日必死，标准模式两个 -10% 天必死）。这不是疏漏，是设计意图——要让玩家亲手体会满仓借贷的险恶。
- **利息按账龄递增**：日息 = 余额 × 年化 ÷ 本局年交易日数。年化从 `SHARK_ANNUAL_BASE`（24%，标准 1%/天、快速 2%/天）起，账龄每满 `SHARK_RATE_STEP_DAYS`（5 个计息日）上调一档 `SHARK_ANNUAL_STEP`（12%），封顶 `SHARK_ANNUAL_MAX`（72%）。利息滚进本金，**越拖越贵是复利不是加罚**。
- **一笔一台账**：`user_shark_loan` 一行一笔，各自带 `start_day` 与 `due_day`（= 起算日 + 本局一个游戏年：标准 24 天、快速 12 天）。日息不落库，按账龄现算，免得改了规则旧行还对不上。提前还款按到期日近的优先冲销。
- **到期必须还**：到期日收盘先扣现金；不足则按市值从大到小强制卖出持仓冲账（**停牌 / 跌停封死 / T+1 未解冻的跳过**，与券商强平同一套跳过规则）。卖得掉就结清，卖不掉的转为 OVERDUE，继续按封顶利息滚、每天催债。
- **与融资的口径分界（关键）**：维持担保比例**只看融资债**——券商不为民间借贷平仓；但净资产与资不抵债判定**看两种债合计**（`sys_user.debt` 与 `sys_user.shark_debt` 分列两栏）。所以借满高利贷之后融资额度会被同一条"累计负债 ≤ 净资产"规则挤掉，且一个跌停日就能让净值归零直接爆仓，而不是等着被谁平掉。
- **播报只在节点**（不每天刷屏）：到期强卖 > 逾期 > 到期结清 > 临近到期（剩 3 天 / 剩 1 天）> 利率涨档，其余日子静默；但利息每天照滚、`SHARK_INTEREST` 流水每天照记。
- **风险提示**：板块告示（`content/shark-lines.txt` 的 `@WARNING`）+ 点「借」时的二次确认，确认框里给出**这笔的到期日、第一天利息、递增与封顶规则、卖不掉会怎样**——把话说明白，借不借是玩家的决定。

## 7. 消息与主力博弈系统（趣味性核心）

### 7.1 主力剧本引擎

每个账户世界中，调度器按概率（约每 20\~40 跳掷骰）为一只**未停牌、无进行中剧本**的股票启动剧本。剧本 = 分阶段定向价格漂移 + 配套消息编排，状态保存在内存。

**剧本一：洗盘吸筹（SHAKEOUT）**

1. *恐慌期*（1\~3 跳）：放出**假利空传闻**（股吧/内幕来源），价格急跌甚至跌停；
2. *磨底期*（5\~15 跳）：低位窄幅震荡，逼散户割肉；
3. *拉升期*（10\~20 跳）：主力强拉，价格创新高；期间或之后公司发布**辟谣公告**（传闻证伪）。

- 玩家博弈：恐慌割肉 = 被洗出局；拿住或抄底 = 获利。

**剧本二：拉高出货（PUMP\_DUMP）**

1. *拉升期*（若干跳）：连续拉涨停（2\~4 板），配套**假利好传闻/内幕**（重组、大单、爆款），股吧狂欢氛围；
2. *出货期*（5\~10 跳）：高位剧烈震荡、涨停反复打开；
3. *崩盘期*（2\~4 跳）：断崖跳水连跌停，同期或事后出现**公司澄清公告/监管问询函**（传闻证伪）。

- 玩家博弈：追高接盘 = 站岗；提前潜伏、高位不贪 = 获利。

**剧本三：尾盘偷袭（TAIL\_WHIP）**

- 下午盘最后 3\~5 跳，价格被突然急拉或急砸 5%\~10%（受涨跌停夹逼），无消息配合，操纵收盘价与次日涨跌停基准。

**剧本四：天地板 / 地天板（SKY\_EARTH）**

- 极端形态：一跳内从涨停砸到跌停（天地板，常伴随午间"窗口指导"类传闻，见 §7.4）或从跌停拉回涨停（地天板）。作为洗盘/出货剧本的高潮事件独立触发；封板状态机的炸板机制（§5）同样会自然产生天地板。

### 7.2 消息体系：来源分级与真伪生命周期

每条消息带来源标签，发布时**不标注真假**，玩家依据来源可信度自行判断：

| 来源                 | 标签颜色 | 可信度                  | 特点                              |
| ------------------ | ---- | -------------------- | ------------------------------- |
| 权威公告（公司公告/证监会/交易所） | 红    | 必真                   | 滞后——落地时价格往往已反映；发布即"证实"态         |
| 财经媒体               | 黄    | 高（约 80% 真，小概率失实事后辟谣） | 速度快                             |
| 股吧传闻               | 灰    | 低（约 45% 真）           | 噪声与水军带节奏阵地，小作文发源地               |
| 神秘内幕               | 紫    | 不定（约 70% 真）          | 仅持仓该股收到，提前 30\~60 秒到达，但可能是主力放的饵 |
| 玩梗氛围               | 绿    | 无真假（FUN）             | 名梗/段子/魔咒，零价格冲击或仅作反向指标，见 §7.3 池④ |
| 营业部 NPC            | 蓝    | 角色设定（见下）             | 张大妈/老王/保安老李/首席，见 §7.3 池⑤        |

**真伪三态**：`PENDING`（传闻/未证实）→ 后续揭晓为 `CONFIRMED`（证实）或 `DENIED`（辟谣证伪）；部分传闻保持 PENDING 不了了之。揭晓消息通过 `followup_of` 关联原消息，在数跳后、午休或盘后到达（如"【辟谣】獐岛水产：火山扇贝传闻严重失实"）。玩梗/NPC 消息无三态。

### 7.3 事件库体系（五大事件池 + 七种反应模式）

事件采用**组合式事件工厂**（不做线性模板堆砌）：内置 **160 个事件骨架**（`EventSkeleton`：code、scope、来源、适用纪元标签、权重、目标选择器、impact\_pattern、幅度/持续跳数区间、三态概率；按 scope 分布为 **STOCK 95 / SECTOR 50 / MARKET 15**）；每个骨架配 **2\~3 个行业/个股变体文案**（文案本体在 `resources/content/event-copy.txt`，见 §7.8）（"业绩暴雷"骨架：水产→扇贝跑了、医药→疫苗失败、科技→流片失败、地产→债务违约、白酒→库存失踪…），文案中金额/股吧 ID/日期/张大妈后缀吐槽等槽位运行时随机填充。三层组合（骨架 × 变体 × 槽位）使玩家实际感知 **500+ 不重样事件**。运行时掷骰抽取实例 → 写 user\_message + game\_event + 按 impact\_pattern 生成 PriceShock（§5）。

**股吧弹幕流**（氛围文案库，全部在 `resources/content/`，见 §7.8）：不进消息中心、不落库，通过 `/user/queue/danmu` 推送，在个股页的**股吧标签页**里按帖子流展示（最新在上），同时在**分时图与日K图的绘图区内以轻量弹幕飘过**（不挡鼠标，完整列表仍看标签页）；大盘页不再放飘屏。
- **每只票各自成流**（2026-10-20 改）：按"热度"给每只票排**下一次发言的跳号**（冷门票基准 38%，涨跌幅越大话越多，封板再加一档，上限 90%），间隔服从指数分布（1 跳、2 跳、5 跳、9 跳都会出现——固定节奏看着像机关枪）；类别按**该票自己的状态**选（封板→涨停/跌停、|涨跌|>5%→急拉/跳水、>3%→次级、其余→**日常闲聊**；票在动的时候也有 35% 的概率说闲话）；节流**按票计**（同票同类隔 2 跳）。每只票一条自己的随机流，各说各的、不会全场同拍。产出量：实测每票每天约 32 条、热门票 40 条，日常闲聊占一半以上。
- **内容三级混抽**：个股级触发按 50% 该股专属（16 条）/ 25% 所属板块 / 25% 全局类别池抽；其中"日常闲聊"用独立的 `@CHATTER` 池（**370+ 条**，混了短反应"已割/满仓/我在山顶"、吐槽反问"楼上别跑/我谢谢你"、互相回复"说得好我反手加仓"三种体裁），因为这才是股吧里绝大多数帖子。
- 触发条件：个股涨停/跌停/炸板/急拉跳水（"老师明天还涨吗""已挂涨停价瑟瑟发抖""关灯吃面""核按钮已按"）、指数大涨大跌（"4000 点指日可待""股灾又来了"）、横盘冷门（"这票是不是死了"）；弹幕随机带股吧 ID 与点赞数，纯氛围零价格影响。

**池① 个股基本面（约 61 条 fund 骨架，scope=STOCK，权威/媒体来源）**：业绩预增/首亏/扭亏/变脸、清仓式减持（"为偿还个人借款""孩子留学"）、增持回购、高送转（10 转 20）、限售解禁、定增、股权激励、立案调查、高管失联/被查、商誉减值、审计"无法表示意见"、产品涨价/降价、中标大单、芯片流片成功/失败、新药临床数据、被列入实体清单、互动易蹭热点（"公司目前没有相关业务，未来不排除"）、改名沾科技热点、龙虎榜上榜、ST 戴帽/摘帽、分红、调入指数、券商首次覆盖给"买入"评级、跨界收购热门赛道、安全事故、环保处罚等。按板块路由（海产梗→獐岛水产、医药梗→恒瑞药堂、科技制裁→科技股池）。

**池② 板块政策（约 59 条 policy 骨架，scope=SECTOR 45 + MARKET 14）**：降准降息、印花税调整、IPO 节奏收紧/放松、国家队入场、监管喊话严打游资、医药集采、碳中和补贴、地产三支箭、猪周期（猪价起飞/回落）、锂价/硅料价格战、白酒批价涨跌、美联储加息、美股暴跌跟跌、英伟达链景气、题材风口（AI/低空经济/机器人/稳定币/元宇宙等，按纪元标签加权出现）。

**池③ 传闻小作文（约 40 条 rumor 骨架，股吧/内幕来源，走三态）**：股吧小作文（"据传 XX 股份将停牌重组，目标价翻倍"）、券商首席电话会议纪要"泄露"、大 V 喊单、内部人士消息（仅持仓该股 70% 概率送达）、"老师明天带你们打板"。约 45% 为真，1\~3 天内由公司澄清公告证实/辟谣。经典套路**买传闻卖事实**：传闻拉起 → 权威公告"证实"当日反而高位出货。

**池④ 玩梗氛围（无独立骨架，FUN 来源文案，零价格冲击或反向指标）**：海鲜股"扇贝跑了→又跑了→自己回来了"三连、关灯吃面、为国护盘、"4000 点是牛市起点"体、券商策略会魔咒（会期大盘易跌）、丁蟹效应、两桶油拉升护盘魔咒、"问君能有几多愁，恰似满仓中石油"、核按钮与天地板吐槽、销户文学、"侠之大者为国接盘"、停车场车满为患情绪指标、"这轮不一样"、牛市旗手券商暴动段子等。

**池⑤ NPC 角色线（蓝标，贯穿全剧的老面孔，按游戏日进度编排+随机穿插）**：

- **营业部张大妈**：荐股反向指标——她高调喊冲的票 65% 概率随后下跌（"我外甥在上市公司当保安，内部消息，明天涨停！"）；偶尔蒙对后更加自信；股灾纪元哭晕在大厅。

- **隔壁老王**：玩家对照组——总在错误时点满仓/割肉，"老王上周把房子抵押满仓了科技股"；黑7月后推送"老王这周没再来营业部，听说去天台排队了"；通关时可看到老王的最终收益率对比。

- **保安老李**：扫地僧情绪指标——"今天停车场车又满了，我守了八年，每次这样都没好事"（疯狂日/顶部预警）、"营业厅好久没这么冷清了"（底部暗示）。

- **首席分析师**：一本正经胡说八道——"目标价上调至 88.48 元，维持买入评级"、"短期震荡，长期向好"（任何行情都适用）。

**@玩家 互动事件**（根据玩家当日操作生成，FUN/NOTIFY 来源）：追高涨停板后盘后推送"XX 股龙虎榜：知名游资一日游，散户大本营接盘"；跌停割肉次日该股涨停推送"股吧热议：昨天割肉的老师还好吗"；满仓融资后推送"系统提醒：您的担保比例已引起营业部主任注意"；长期空仓后大妈吐槽"年轻人钱存银行怎么跑赢通胀"。

**七种价格反应模式**（impact\_pattern 字段，决定冲击怎么作用于行情）：

1. 一步到位：政策/制裁类，跳空或直接封板；
2. 脉冲回落：盘中急拉 3\~6% 后数跳内回吐，追高即套；
3. 买传闻卖事实：传闻期持续小漂移，证实当日反向出货；
4. 延迟发酵：消息落地后 10\~30 跳缓慢同向漂移；
5. 过度反应反转：首日过度冲击，次日反向修正 30%\~50%；
6. 利空出尽/辟谣砸盘：辟谣后小概率照涨（"利空出尽是利好"），证实利好小概率照跌；
7. 连环发酵：制裁→跌停→停牌→复牌补跌（跨多日，配合 halt 机制）。

玩梗事件约两成零冲击，纯氛围/考验分辨力。

### 7.4 全时段消息与隔夜跳空

- **盘中消息**：开盘期间按 §7.1/§7.2 节奏触发事件、传闻、内幕、辟谣。

- **午休消息**（LUNCH\_BREAK 期间）：抽取 0\~2 条午间消息（业绩预告、监管函、"窗口指导"传闻等）。造成的价格冲击以跳空形式作用于**下午盘首跳**（下午 open = 上午收盘价 × (1+冲击)，夹逼涨跌停）；"窗口指导"类传闻可直接引发下午开盘天地板。

- **盘后消息**（SETTLING/CLOSED 期间）：抽取 0\~2 条盘后重磅（立案调查、重组公告、政策发布），冲击幅度写入 `user_stock_state.gap_pct`。

- **隔夜跳空**：次日开盘首跳 `open = prev_close × (1 + gap_pct)`；|gap| ≥ 10% 时开盘即封涨停/跌停（一字板，首跳锁定买/卖方向不可成交）。

- **政策面全市场事件**（scope=MARKET）：降准降息、印花税下调（利好全市场，全部股票正向 gap + 当日漂移偏移）、监管严打异常交易（利空连板股）、外部冲突等。作用于 24 只股票与指数。

### 7.5 停牌核查（小黑屋）

- **异动公告**：股票连续 2 个交易日收涨停，发布《股票交易异常波动公告》（权威消息，纯提示）。

- **停牌核查**：连续 3 个交易日收涨停（或 5 日内 4 板），次日起停牌 1 个游戏交易日：`halted = true`、`halt_until_day = current_day + 1`；停牌期间该股冻结、不可交易；推送"停牌核查"系统通知。

- **复牌**：到达 halt\_until\_day 的开盘时自动复牌；复牌首日大概率补跌（gap −5% \~ −10%，小概率继续涨停——"妖股出关"）。复牌后连板计数清零。

### 7.6 事件触发频率

- 盘中：每 10~~20 跳掷骰触发一次"事件/剧本"（按 90 跳/天节奏，剧本与普通事件合计约 3~~5 次/交易日）；其中主力剧本（§7.1）占比约 35%，五池事件（§7.3）约 65%；特殊剧本日（§4.4）优先且不占掷骰名额。

- 事件抽取：按当前纪元标签过滤适用模板 → 按权重随机；目标股由模板选择器决定（持仓股加权——自己的股票更容易出新闻，增强代入感；NPC 荐股从全市场随机）。

- 午休：0~~2 条消息；盘后：0~~2 条消息；政策面全市场事件按纪元编排触发。

- 内幕消息：按剧本编排发放（持仓该股才收到），70% 概率送达。

- NPC 消息：每个交易日约 1\~2 条（张大妈荐股/老李情绪/首席观点/老王动态），按游戏日进度节点穿插角色线（如黑7月老王失踪、通关收益率对比）；@玩家事件在满足触发条件（追涨停/割肉跌停/满仓融资/连续空仓等）时于盘后或次日开盘前推送，每日至多 1 条防刷屏。

### 7.7 营业部生态与进度系统（中期目标感）

- **NPC 台词库**：四个角色线场景（张大妈荐股、老李停车场、龙虎榜、割肉热议）各有 5 条台词随机抽；8 位 NPC 各有 5 句性格闲聊，每日约 45% 概率由一位在场 NPC 说一句（文案在 `resources/content/npc-lines.txt`，读取入口 `game/content/NpcLines.java`）。
- **板块消息库**：21 个板块 + 大盘各有权威公告/媒体报道/股吧传闻（含配套证实·辟谣追报）/玩梗段子（文案在 `resources/content/sector-flavor.txt`，读取入口 `game/content/SectorFlavor.java`），板块级与全市场级事件 55% 改用对应板块文案，标题与正文成对替换。
- **营业部收益排行榜**：8\~10 名虚拟散户与玩家同榜——张大妈（追涨杀跌型）、隔壁老王（高杠杆追热点）、保安老李（定投指数型，常年暗赚）、"炒股养家居士"（死捂一只不动）、"拆迁户老钱"（满仓招笑银行吃股息）、"95 后新基民"（追题材风口）、"辞职炒股的程序猿"（量化幻觉型，频繁交易亏手续费）等。每个 NPC 的日收益率由基于世界种子的规则函数生成（策略画像决定 β/换手/踩点倾向），每日收盘结算后更新排名，推送"今日营业部榜"（玩家排名高亮）。黑7月纪元老王与新基民排名标记"已销户/天台排队中"；通关结算页展示本局最终榜与各 NPC 结局小剧场。

- **资产段位**：按当日净资产（峰值进阶、跌破降级）评定：散户（<15 万）→ 中户（15 万）→ 大户（30 万）→ 游资（60 万）→ 牛散（100 万）。状态条常驻当前段位；升级推送"营业部主任亲自给您递烟"，降级推送玩梗通知（"您已跌回中户室，张大妈表示慰问"）。

- **阶段挑战徽章**（达成给称号/徽章，不给现金，防经济崩坏）：如"空仓躲过一次千股跌停""抓住一只 5 连板""单日收益跑赢指数 5%""打新中签""连续 10 天不操作（捂股大师）""股灾纪元净资产不创新低"等，随纪元进度解锁检测，推送祝贺消息。

## 8. 并发控制（核心技术指标）

- **悲观锁（交易主路径）**：交易方法 `@Transactional(rollbackFor = Exception.class)`，事务内：

  1. `SELECT ... FOR UPDATE` 锁定 `sys_user` 账户行；
  2. 再 `SELECT ... FOR UPDATE` 锁定该股票的 `user_position` 行（不存在则插入，重复插入依赖唯一索引兜底后重查加锁）；
  3. 固定加锁顺序：先账户行、后持仓行，防止多事务死锁；
  4. 扣减/增加 balance、更新持仓、写 trade\_record，同事务提交。

- **乐观锁（行情快照）**：`user_stock_state.version`，快照更新失败重试至多 3 次。

- **并发场景**：同一账户多标签页 / 双击 / 脚本重放导致的瞬间并发下单；行情线程与交易线程并发读写。

- 辅助手段：前端按钮点击后置灰防连点；REST 层基础参数校验。

- 全部为用户私有目的地（点对点，无全局广播），实际只有 **4 条**：

| 目的地                         | 内容                                                                   | 时机                |

| `/user/queue/messages`      | 新消息（公告/媒体/传闻/内幕/玩梗/NPC/辟谣，含来源与三态）                                    | 消息产生时（盘中/午休/盘后）   |
| `/user/queue/danmu`         | 股吧弹幕（短评论文案，不进消息中心）                                                   | 行情触发（涨停/跌停/急拉/横盘） |
| `/user/queue/notifications` | 系统通知：停牌/复牌、隔夜跳空、结算评价、称号/徽章解锁、段位升降、纪元切换、熔断、追保/强平/爆仓、打新申购/中签/上市、排行榜、通关 | 事件发生时             |

## 10. 数据模型

所有金额使用 `DECIMAL(12,2)`，价格 `DECIMAL(10,2)`。**字段清单的权威是 `src/main/resources/db/schema.sql`（16 张表）**，
本节只记"为什么这么分表"——把列抄进文档必然与代码漂移（历史上票名改过 9 次、`index_value` 单列两用埋过雷）。

| # | 表 | 角色 | 为什么要单独一张 |
| --- | --- | --- | --- |
| 1 | `sys_user` | 账户与钱 | `debt`（融资债）与 `shark_debt`（高利贷余额）分列：担保比例只读前者，净资产读两者之和（§6.6） |
| 2 | `stock_info` | 24 只票静态档案 | 全服共享只读；行情状态按账户隔离，另立 `user_stock_state` |
| 3 | `user_stock_state` | 每账户每票行情状态 | 同一只票在不同账户的停牌/连板/ST 状态可以不同（世界按账户推进）；`version` 是乐观锁 |
| 4 | `user_position` | 持仓 | `available_shares` 承载 T+1 解冻 |
| 5 | `trade_record` | 成交流水 | 只追加，供资产页三类流水 |
| 6 | `loan_record` | 借贷流水 | `loan_type` 覆盖融资四类与高利贷四类（`SHARK_BORROW/REPAY/INTEREST/LIQUIDATE`）；它是流水不是台账 |
| 7 | `user_shark_loan` | 高利贷台账 | 一笔一行、各自带起算日与到期日；日息不落库（按账龄现算），`sys_user.shark_debt` 是它的汇总缓存 |
| 8 | `game_event` | 事件与剧本留痕 | 带 `impact_pct`/`impact_pattern`，与消息中心分离：那是给人看的，这是价格冲击的账 |
| 9 | `user_message` | 消息中心 | `truth_status` + `followup_of` 支撑传闻→证实/辟谣链；`sector` 让个股页能捞回板块级消息 |
| 10 | `user_game_state` | 每账户一行的世界时钟 | `prev_index`（当日开盘基准）与 `index_value`（盘中当前值）**必须分列**：合一时盘中 checkpoint 会把熔断阈值基数覆盖成盘中值；`game_mode` 让节奏一局一定 |
| 11 | `user_title` | 称号与徽章 | 徽章只给称号不给现金（防经济崩坏） |
| 12 | `user_era` | 本局 11 纪元时间表与强度参数 | 注册时一次掷出落库，重启与快进都读它（同 seed 同结果） |
| 13 | `user_script_day` | 本局剧本日 + IPO 排期 | 同上，保证名场面每局保证发生且时点可复现 |
| 14 | `user_daily_snapshot` | 每日收盘快照 | 曲线、排行榜、终局结算的唯一数据源；`shark_debt` 一并入快照 |
| 15 | `stock_daily_bar` | 每账户每票每交易日 OHLC | 日K 数据源；必须在结算重置 OHL **之前**写入，快进与逐跳同路径 |
| 16 | `user_ipo_record` | 打新记录 | 状态机 SUBSCRIBED→WON/LOST→PAID→SETTLED/ABANDONED |

**注册事务内自动播种**：创建 sys\_user（balance=100,000, debt=0）+ user\_game\_state（current\_day=1, market\_state=NOT\_STARTED, tick\_index=0, index\_value=1000, vol\_regime=NORMAL, tier=RETAIL, world\_seed=随机 long）+ 24 行 user\_stock\_state（current/open/high/low/prev\_close 均 = base\_price, is\_st=false）+ **调用世界排期器（基于 world\_seed）掷出 11 行 user\_era（边界抖动 + 强度参数）与全部 user\_script\_day（剧本日 + 每年 2\~3 次 IPO 排期）**；同时写入第 0 天 user\_daily\_snapshot 作为排行榜与曲线起点（NPC 初始资产均 100,000）。

### 称号一览

称号与徽章的**清单与解锁条件以 `game/constants/Titles.java` 为准**（结算/成交时检测，解锁推通知）。
设计约束只有两条：徽章**只给称号不给现金**（否则会变成刷钱目标）；`title_name` 落库存中文，前端不再抄一份映射。

## 11. REST API 概览

> 端点清单以 `web/` 下的控制器为准，本节只记契约与出参要点。新增/变更接口时同步本节。
> 新增/变更接口时同步改本节，勿让规格与实现漂移。

- `POST /api/auth/register`（body 可选 `mode`：STANDARD/QUICK，缺省 STANDARD）、`POST /api/auth/login`（返回 JWT）

- `GET  /api/me`：当前登录用户（userId、username），前端刷新后恢复身份用

- `GET  /api/me/assets`：现金、市值、融资负债、高利贷余额、净资产、担保比例、**融资可借额度**（`borrowable` 由服务端计算，前端不再自己估）

- `GET  /api/me/positions`：持仓列表（含可卖股数、成本、浮盈、停牌标识）

- `GET  /api/me/trades`：交易流水分页

- `GET  /api/me/loan-records`：融资流水分页（loan\_record，新在前）

- `GET  /api/me/ipo-records`：打新记录分页（user\_ipo\_record，新在前）

- `GET  /api/me/titles`：已解锁称号与挑战徽章（kind 区分）

- `GET  /api/market/equity-curve`：全剧（72 天）净资产 vs 百年指数曲线（来自 user\_daily\_snapshot，终局页/资产页用）

- `GET  /api/market/leaderboard?gameDay={n}`：营业部排行榜（玩家 + NPC 当日资产、排名、状态）；默认最新结算日

- `GET  /api/stocks`：24 只股票静态信息 + 本账户最新行情

- `GET  /api/stocks/{id}/quotes`：当日分时点序列（固定 90 点时间轴，未到点为 null、午休断轴）

- `GET  /api/stocks/{id}/danmu`：该股的股吧近期弹幕（2026-10-20 新增）——这只票专属 + 不点名的大盘闲聊，按 `seq` 升序。弹幕只在盘中实时推，前端只留 30 条环形缓冲的话 24 只票一分、个股页几乎总是空的；后端按账户留一份每股历史，这个接口一次拉回来

- `GET  /api/stocks/{id}/kline?limit=60`（**默认 60，前端一次取 200**）：日K蜡烛数据（来自 stock\_daily\_bar，快进与正常推进同路径落库）；`limit` 上限是「本局交易日 + 20 根开局前历史」，前端一次要满，屏上显示多少根由图表的槽位口径决定（见 implementation-notes §3）。**四个价是前复权价**（最新一根＝真实成交价，越往前可能被除权除息压得越低），`changePct` 仍是当日真实涨跌幅、不受复权影响，所以图的高度差与 tooltip 的数字必然一致

- `GET  /api/market/index`：百年指数当日分时与收盘历史

- `POST /api/trade/buy` `{stockId, shares}`、`POST /api/trade/sell` `{stockId, shares}`

- `POST /api/loan/borrow` `{amount}`（融资借款，校验累计负债 ≤ 净资产）、`POST /api/loan/repay` `{amount}`（还款）

- `GET  /api/loan/shark`、`POST /api/loan/shark/borrow` `{amount}`、`POST /api/loan/shark/repay` `{amount}`（高利贷，§6.6）：三者都返回 `SharkLoanDTO`——未清余额、今日利息、今天按几倍年化、最早到期日与剩余天数、还能借多少、逐笔台账，**外加规则参数（额度倍数 / 起始与封顶年化 / 升档步长 / 期限 / 本局年交易日数）与告示文案**（`content/shark-lines.txt` 的 `@WARNING`）：前端只渲染，不在页面里另抄一份规则或文案

- `POST /api/ipo/subscribe` `{scriptDayId}`：新股顶格申购（申购日当日有效，幂等）

- `GET /api/auth/local/status`（仅 portable 档）：本地存档概况 `{local, hasSave, day, totalDays, modeLabel, marketState, finished, netAsset}`，前端开页先探它——**先当单机、再当多人**，404 才渲染登录/注册。 `POST /api/auth/local/resume` 继续游戏（发免密令牌）、`POST /api/auth/local/new` 创建新游戏（无本地玩家就建，有就清空重播）。这三个接口挂在 `/api/auth/**` 下复用既有放行规则，不改鉴权表。

- `POST /api/game/restart` `{mode?}`：开新的一局——用新种子重新播种（清空持仓/行情状态/快照/消息/融资流水/成交/纪元/剧本日/打新记录/称号/事件/**日K**，账户资金与 game\_state 复位，保留账号密码）。`mode` 省略则沿用本局模式。**两种时机可调用**：终局后"再来一局"，以及注册后还没开过局（第 1 天、零成交零持仓）——模式是**一局一选**的，不在注册时绑定。本局进行中调用一律拒绝。

- `GET  /api/game/result`：终局结算页数据（结局类型、存活天数、**终局负债**（爆仓页"负债 X"取这个字段，盘中爆仓没有收盘快照，只能取账户现值）、总收益率、指数涨幅、最终段位、强平记录、本局种子号、全剧资产 vs 指数曲线、**营业部最终排行榜与 NPC 结局小剧场**）

- `GET  /api/game/modes`：本局可选模式清单（`code`/`label`/`description`/`totalDays`），由 `GameMode` 枚举直接下发，供"开新局选模式"的选择器使用——前端不再另抄一份模式文案。

- `GET  /api/market/state`：market\_state、current\_day（年/第几天）、当前纪元名称与叙事、当前段位、tick\_index、**本会话剩余跳数**的阶段倒计时（早盘 45−tick、午盘 90−tick，非交易态 0，绝不返回负数）、新手引导步骤；另下发本局档案 `mode/tickMs/daySeconds/totalDays/limitPct`

- `POST /api/market/start`：开始第 1 天 / 下一交易日（幂等）

- `POST /api/market/skip`：跳过当日/下一交易日（快进模拟至收盘并结算），返回收盘总结 DTO（§12.7）；终局态拒绝。
- `POST /api/market/pause` / `POST /api/market/resume`：暂停/恢复**本账户**世界的实时推进（重要消息模态弹窗期间冻住房价，玩家关掉弹窗即恢复）。只动内存标记，不改价格与库内状态，也不拦快进与结算；页面重新加载且没有待看弹窗时会自动 resume，防止世界被冻死。

- `GET  /api/market/daily-summary?gameDay={n}`：某日收盘总结数据（默认最近结算日）：日收益率、指数日涨跌幅、资产快照、担保比例、当日要闻列表、T+1 解冻/追保/强平/停牌提示、玩梗评语、当前纪元与明日风险提示。

- `GET  /api/messages`（按来源/三态/已读/交易日/**stockId**/**includeSector** 筛选；includeSector=true 时连同该票所属板块的板块级消息一起返回）、`PUT /api/messages/{id}/read`、`PUT /api/messages/read-all`（全部已读，铃铛清红点）
  个股详情页凭 `stockId` 向服务端要**这只票的历史消息**，不再"拉全局最新 100 条再在前端挑"。

5. **消息中心页**：消息按重要性分四级呈现。**第一级 ALERT（模态弹窗 + 暂停行情）**：后端 `NotifyPublisher.alert` 落 `type=ALERT`，只给"钱已经出事或马上出事"的账户级消息——追保、强制平仓、爆仓、高利贷到期强卖与逾期、停牌潮；全屏遮罩、必须玩家亲手点掉，期间服务端暂停这一份世界的推进（`POST /api/market/pause`/`resume`），多条排队一条条看完。分级口径在服务端判定，前端只认 `type`，不再按标题猜。

6. **营业部排行榜页（可与收盘总结合并入口）**：当日/历史收益排行（玩家高亮 + 8\~10 个 NPC 带头像、持仓风格标签、状态"天台排队中/已销户"），点击某日可看历史排名。
7. **收盘总结弹窗/页**（每日结算后及快进返回时弹出，CLOSED 状态可随时重看）：① **今日战绩**——你的日收益率 vs 百年指数涨跌幅、跑赢/跑输徽章，现金/市值/负债/净资产/担保比例快照、**当日营业部排名**；② **今日要闻**——当天剧本日/事件/传闻/辟谣标题列表（快进漏掉的戏补看，点击跳消息中心）；③ **结算提示**——T+1 解冻股数、追保/强平/停牌/熔断/打新中签或上市结果通知；④ **玩梗评语**——根据收益率 vs 大盘、当天事件、纪元背景随机生成的一句"营业部体"点评；⑤ **明日提示**——当前纪元背景与杠杆风险提示（如"你正处于股灾纪元，高担保比例请注意风险"）；底部按钮"开始下一交易日 / 再看一眼行情"。
8. **终局结算页**：天台结局（爆仓：负债 + 存活天数 + 三段黑白分镜）/ 通关成绩单（72 天）：总收益率、指数涨幅、最终段位、全剧净资产 vs 指数曲线、**营业部最终排行榜与 NPC 结局小剧场、本局种子号**、**"再来一局"按钮**（新种子重排纪元/剧本/事件）；数据来自 `GET /api/game/result`。

WebSocket 连接登录后建立，断线自动重连；快进期间不推送，结束后前端拉取总结并刷新全量状态。

## 13. 错误处理

- 业务异常统一 `BusinessException` + `@RestControllerAdvice` 返回标准错误码与文案。

- 明确文案场景：未登录 / token 过期、休市中拒单、非整手、涨停封死拒买（"涨停封死，买单排不上"）、跌停封死拒卖（"跌停封死，卖不出去"）、停牌拒单、资金不足、可卖股数不足、股票不存在、重复开盘（幂等返回当前状态）、终局态跳过/交易拒绝、融资额度不足、还款金额超过负债。

- WebSocket 推送失败不影响交易主流程；消息推送失败仅记录日志。
