## 1. 项目概述与目标

基于 Spring Boot 的微型虚拟股市模拟游戏。后端定时任务驱动行情、WebSocket 实时推送、数据库事务与锁保障交易一致性，用于深度练习 Spring Boot 企业级技术栈。

**核心模式：账户隔离的单机存档游戏。** 每个注册账户拥有一个完全独立的游戏世界：独立的交易日进度、行情序列、突发事件、主力剧本。玩家扮演资金量不影响市场的散户，按当前价与系统成交；除涨跌停板与停牌限制外均可成交。各账户之间互不可见、互不影响。

**博弈主题：与"主力"斗智斗勇。** 行情不只是随机游走——系统会以 NPC 庄家身份按现实 A 股套路运行操盘剧本（洗盘吸筹、拉高出货、尾盘偷袭、天地板），并配套释放真假难辨的消息（假利空吓人割肉、假利好诱人接盘）。消息有来源分级与"传闻→证实/辟谣"生命周期，玩家靠信息辨别力与心态获利。

练手目标覆盖：Spring Security + JWT 认证、Spring WebSocket（STOMP）点对点推送、定时调度与线程隔离、MyBatis-Plus、MySQL 悲观锁（SELECT ... FOR UPDATE）与乐观锁（version）、高并发下资金安全验证。

## 2. 技术栈

- **后端**：Spring Boot 4.1.1、Java 17、MyBatis-Plus、MySQL 8（InnoDB）、Spring WebSocket（STOMP 子协议）、Spring Security + JWT（jjwt）、Lombok、spring-boot-starter-validation、springdoc-openapi（接口文档）。

- **前端**：Vue 3 + Vite + Element Plus + Pinia + Vue Router + axios + ECharts（分时图）+ @stomp/stompjs（WebSocket 客户端）。

- **形态**：前后端两个独立工程；后端仅提供 REST + WebSocket。密码使用 BCrypt 加密。

- **线程模型**：Tomcat 线程处理 HTTP 请求；行情/剧本/事件/时钟推进运行在独立调度线程池，与 HTTP 线程隔离。

## 3. 游戏时间与市场状态机

时间常量（可配置）：

| 参数     | 值                             |
| ------ | ----------------------------- |
| 行情跳价间隔 | 3 秒 / 跳                       |
| 上午盘    | 45 跳（2 分 15 秒）                |
| 午休休市   | 30 秒                          |
| 下午盘    | 45 跳（2 分 15 秒）                |
| 一个交易日  | 现实 5 分钟，共 90 个价格点             |
| 游戏年长度  | 36 个交易日 / 年（1 月 ≈ 3 个游戏日）     |
| 游戏总长度  | 3 个游戏年，共 108 个交易日；满 108 天正常收官 |

市场状态机（每个账户独立）：

```
NOT_STARTED（第 1 天待开盘）
   └─(玩家手动"开始第 1 天")→ MORNING_OPEN
MORNING_OPEN（上午盘 45 跳，行情跳动，可交易）
   ├─ 45 跳结束 → LUNCH_BREAK
   └─ 熔断触发（仅第 2 年纪元 5，指数日内 ≤ -7%）→ SETTLING（当日提前收盘）
LUNCH_BREAK（午休 30 秒，行情停跳，不可下单；发布午间消息）
   └─ 30 秒结束 → AFTERNOON_OPEN（应用午间消息造成的下午开盘跳空）
AFTERNOON_OPEN（下午盘 45 跳，行情跳动，可交易）
   └─ 45 跳结束 → SETTLING
SETTLING（自动收盘结算，瞬间完成）
   ├─ 爆仓（资不抵债）→ BANKRUPT（游戏提前结束）
   ├─ 第 108 天结算完成 → FINISHED（三年期满，正常收官）
   └─ 其他 → CLOSED
CLOSED（已收盘，不可交易；发布盘后消息、结算评价、称号判定、融资计息与担保检查）
   └─(玩家手动"开始下一交易日")→ MORNING_OPEN（current_day + 1，应用隔夜跳空、纪元切换）
BANKRUPT / FINISHED（终局：冻结一切操作，展示结局结算页）
```

关键规则：

- **手动开盘**：`NOT_STARTED` 与 `CLOSED` 状态下，玩家点击"开始 / 下一交易日"才推进；服务端校验状态，重复点击幂等无效。不存在自动跨天。

- **离线暂停**：游戏时间仅在该账户 WebSocket 在线时推进。断开连接时行情停跳、午休倒计时暂停，状态持久化；重连后从断点继续。

- **收盘结算（SETTLING）自动执行**：

  1. 全部股票当前价快照落库；
  2. `prev_close`（次日涨跌停基准）= 当日收盘价；
  3. T+1 解冻：所有持仓 `available_shares = shares`；
  4. 连板统计：当日收涨停的股票 `limit_up_streak + 1`，否则归零；触发停牌核查判定（见 §7.4）；
  5. 融资计息：负债按日利率（年化 8% ÷ 36）计提；随后计算担保比例（总资产 ÷ 总负债）：< 140% 推送追保警告；< 120% 强制平仓（按收盘价依次卖出持仓还债，见 §6.4）；强平后仍资不抵债 → 状态转 **BANKRUPT**（爆仓结局）；
  6. 日收益评价：玩家当日收益率 vs 百年指数当日涨跌幅，推送评价；
  7. 称号成就检测解锁；
  8. 盘后消息抽取（含隔夜跳空幅度，写入 `gap_pct` 待次日开盘应用）；
  9. 重置次日 open/high/low；
  10. 若为第 108 个交易日 → 状态转 **FINISHED**（三年期满收官，生成三年总成绩单）；否则转 CLOSED，推送结算通知。

- **纪元切换**：开盘时按 `current_day` 查本局纪元时间表（见 §4.3），若进入新纪元，推送一条权威/媒体风格的"纪元叙事"消息（如"杠杆牛启动""贸易战打响""黑7月来临"）。

- **熔断提前收盘**：仅纪元 5（熔断开局）期间生效，上午盘指数自昨收跌幅触及 -7% 的当跳 → 立即进入 SETTLING（跳过午休与下午盘），推送交易所权威公告"触发熔断，全天交易结束"。

- **跳过当日（快进）**：NOT\_STARTED/CLOSED 状态下可"跳过下一交易日"，开盘/午休状态下可"跳过当日"（前端二次确认）。服务端对该账户世界执行**完整快进**：从当前时刻起的剩余行情逐跳快速模拟（毫秒级跑完，不推 WebSocket），主力剧本、突发事件、传闻/辟谣、午休/盘后消息照常触发并落库，随后走正常 SETTLING 结算，返回**收盘总结页**数据（见 §12.7）。快进后果真实：T+1 解冻、连板统计、停牌判定、融资计息、追保/强平/爆仓全部照常；熔断日快进触发熔断即提前收盘；第 108 天快进结算后进入 FINISHED。终局态（BANKRUPT/FINISHED）不可跳过。

- **世界锁**：每个账户世界一把 ReentrantLock，调度线程的正常逐跳推进与 HTTP 线程的快进/开盘/结算互斥；调度器拿不到锁（tryLock 失败）则跳过本轮 3 秒 tick。

### 4.3 大行情纪元：三年编年体剧本（宏观系统）

游戏不是无限随机波动，而是一场浓缩 2014H2–2026.8 真实 A 股历史的**编年体大剧**：11 个纪元**按顺序全部发生**（硬保证），但每局的起止时间与强度都有随机性。

**驱动机制**：每个纪元给百年指数一个**市场漂移** μ\_mkt（每跳），给各板块一个**板块系数**（强 = 额外正漂移、弱 = 额外负漂移、中 = 跟随市场）。个股价格 = 随机游走 + μ\_mkt + 板块系数漂移 + 个股剧本/事件漂移。时间换算：游戏年 Y、年中第 D 个交易日（D=1..36），总 `current_day = (Y-1)×36 + D`。

**两层随机（反公式化）**：

1. **存档层（注册时掷一次，持久化到** **`user_era`** **/** **`user_script_day`** **表，重启不变、每局不同）**：

   - **纪元时间表抖动**：纪元边界在基准日上 ±1~~3 天随机（同年纪元不重叠、不留空档、每个纪元最短 3~~6 天、纪元不跨年）。抖动规则：年 1 三个分界基准 D10.5/D20.5/D28.5 分别 ±3/±2/±2 天；年 2 纪元 5 固定从第 1 天开始、长度 3\~5 天，白马/贸易战分界基准 D20 ±3；年 3 分界基准 D12/D24/D32 分别 ±2/±2/±1 天；掷完按顺序裁剪保证最短时长。

   - **纪元强度**：每个纪元的 μ\_mkt 与板块系数在区间内随机取值（同样是疯牛，可能慢牛也可能垂直拉升；黑7月科技股崩多深每局不同）。

   - **剧本日排期**：特殊剧本日（§4.4）在所属纪元内随机落点并持久化。
2. **运行层（每天/每跳随机）**：

   - **波动率体制**：每日 σ 分平静/正常/疯狂三档，且波动聚集（当日体制与前日相关，疯狂日倾向连续，模拟恐慌蔓延）；

   - **反向意外日**：任何纪元每天约 8% 概率出现反向行情（熊市暴力反弹、牛市闪跌洗盘）；

   - 主力剧本的拉板数、砸盘深度、跳空幅度均为区间随机；事件目标股、触发时点随机。

### 4.4 特殊剧本日（历史名场面，保证发生、时点抖动）

剧本日在注册排期时一次性掷出并持久化于 `user_script_day`：**每局保证发生**，但具体游戏日在所属纪元内按下列规则随机，封死比例、目标股等参数亦随机：

- **千股涨停日**：纪元 2 内 1–2 次（随机日）+ 救市次日固定 1 次。开盘 85%\~95% 的股票直接封涨停（买单买不进，幸存股随机），还原 2015 疯牛与救市行情。

- **千股跌停日**：纪元 3 内 2–3 次，**首次锁定纪元 3 第 1\~2 天**（崩盘必以暴跌开场），其余随机；开盘 85%\~95% 股票封跌停（持仓卖不出去，还原"17 个交易日 -34%"的绝望，幸存股随机）。纪元 3 后半段随机安排 1 个**救市日**——央行降息降准 + 国家队入场权威消息，次日千股涨停。

- **熔断日**：纪元 5 第 1、2 个交易日（固定，还原 2016 年 1 月 4 日/7 日）：上午开盘指数即重挫，触及 -7% 当跳触发熔断、当日提前收盘（见 §3）；推送交易所公告。

- **制裁闪崩日**：纪元 7 内 1–2 次（随机日）：权威消息宣布对某科技公司实施出口管制（化用中兴事件），目标股从科技股池随机掷出（片爷科技/通天信联/智算无穷等），连续跌停并触发停牌核查。

- **黑7月崩盘周**：纪元 10 前半段内，科技板块 2–3 个跌停日（具体日随机、板块内目标股随机）、融资盘爆仓潮新闻刷屏；银行/煤炭同日逆势涨停；纪元中段推送"ETF 天量净流入抄底"消息，随后超跌反弹。

特殊剧本日与个股主力剧本（§7.1）可叠加；冲突时以剧本日强制价格行为为准。快进跳过（§3）同样触发剧本日。

## 5. 行情引擎（内存权威 + 快照落库）

- **内存权威**：在线用户的报价保存在内存，键为 `(userId, stockId)`。每只股票一个 `Quote` 对象：currentPrice、open、high、low、prevClose、limitUp、limitDown、limitUpStreak（连板数）、halted（停牌标志），以及当日分时环形缓冲（容量 ≥90 点）。

- **每跳推进**（仅 MORNING\_OPEN / AFTERNOON 状态、且用户在线）：

  1. 基础波动：几何随机游走 `newPrice = price × (1 + μ + σ_day · Z)`，Z 为标准正态随机数，叠加轻微均值回归（向 base\_price 牵引）；**σ\_day 为当日波动率体制**（平静/正常/疯狂三档，按马尔可夫转移逐日掷出、波动聚集，§4.3 运行层随机）；
  2. 纪元注入：叠加当前纪元（查本局 `user_era` 时间表）的市场漂移 μ\_mkt 与板块系数漂移（§4.3）；反向意外日施加反向漂移；特殊剧本日（查 `user_script_day`）执行强制价格行为（千股涨停/跌停锁定、制裁闪崩）；
  3. 剧本注入：主力剧本（§7.1）与事件后果（§7.2）可施加定向漂移/冲击；政策面事件（§7.3）施加全市场同向偏移；
  4. 停牌股票跳过推进（价格冻结）；
  5. 价格夹逼在 `[跌停价, 涨停价]`，四舍五入保留 2 位小数；
  6. 更新 high/low，追加环形缓冲，更新百年指数；检查熔断条件（仅纪元 5，指数日内 ≤ -7% 触发提前收盘）；
  7. 正常推进时推送 `/user/queue/quotes`（24 只行情 + 指数点位）；**快进模式不推送**（结束时一次性返回总结数据）。

- **调度方式**：单线程 ScheduledExecutorService 每 3 秒扫描"在线且开盘中"的用户会话，顺序逐用户推进；推进前 `tryLock` 该账户世界锁，失败则跳过本轮（与快进/开盘 HTTP 请求互斥，见 §3）。

- **快进推进**：`POST /api/market/skip` 持有世界锁，在同一循环内连续跑完当前时刻至收盘的全部跳数（含午休消息、剧本日、熔断判定），随后直接执行收盘结算流程（§3），返回收盘总结 DTO（§12.7）。快进期间所有消息/事件正常落库，仅省略 WebSocket 推送与 3 秒等待。

- **快照落库**：每 30 秒及收盘时，批量 UPDATE `user_stock_state`，使用 MyBatis-Plus `@Version` 乐观锁，冲突重试至多 3 次；同时持久化 `user_game_state.tick_index` 用于断点恢复。

- **交易读价**：交易服务直接读内存现价，无数据库 I/O；内存读使用 volatile/CAS 保证可见性。

- **重启恢复**：内存行情从 `user_stock_state` 最近快照重建；主力剧本为内存态，重启后当前剧本中断（后续随机新剧本），当日分时环形缓冲以快照价重新累积（属可接受取舍）。

## 6. 交易规则与资产

### 6.1 交易规则

- **整手交易**：买卖数量必须为 100 的整数倍。

- **涨跌停**：涨停价 = round(prev\_close × 1.10, 2)，跌停价 = round(prev\_close × 0.90, 2)。**涨停时拒买、跌停时拒卖**；反方向不受限。

- **T+1**：买入当日增加 `shares` 但不增加 `available_shares`；收盘结算解冻后才可卖出。

- **交易时段**：仅 MORNING\_OPEN / AFTERNOON\_OPEN 可下单；午休、收盘、未开盘状态拒单。

- **停牌核查**：`halted = true` 的股票不可买卖（提示"该股票正在停牌核查中"），行情冻结、持仓保留。

- **成交价**：下单瞬间的内存现价。玩家资金量不影响市场，无库存概念，不撮合。

### 6.2 费用与资金

- 新账户初始资金：100,000.00 元。

- 佣金：双边收取，`max(成交金额 × 0.0003, 5)` 元。

- 印花税：仅卖出收取，`成交金额 × 0.001`。

- 买入总支出 = 成交金额 + 佣金；卖出净收入 = 成交金额 − 佣金 − 印花税。

- 成本均价（买入后）：`new_avg_cost = (old_shares × old_avg + 成交金额 + 佣金) / new_shares`；卖出不改变 avg\_cost。

- 资产看板：可用现金 = balance；股票市值 = Σ(currentPrice × shares)（停牌股按停牌前价格）；总资产 = 现金 + 市值；**净资产 = 总资产 − 负债（融资借款）**；总盈亏 = 净资产 − 100,000；浮动盈亏 = Σ((currentPrice − avg\_cost) × shares)。

### 6.3 下单校验链（按顺序短路）

1. 已认证；
2. 市场处于开盘状态（否则"休市中，无法下单"）；
3. 数量为 100 的正整数倍；
4. 股票存在且未停牌；
5. 买入：currentPrice < limitUp（涨停拒买）；卖出：currentPrice > limitDown（跌停拒卖）；
6. 买入：balance ≥ 成交金额 + 佣金；卖出：available\_shares ≥ 委托数量；
7. 执行事务。

### 6.4 融资贷款与爆仓

- **借款**：可随时向券商融资，累计负债上限 = 净资产 × 1（1:1 杠杆）；借款即时到账 balance，debt 增加。

- **还款**：可随时用现金归还负债（金额 ≤ min(现金, 负债)），不计违约金。

- **计息**：每个交易日收盘结算时，`debt ×= (1 + 日利率)`，日利率 = 8% ÷ 36（年化 8% 按游戏日折算）。

- **担保比例** = 总资产 ÷ 负债（负债为 0 时不检查）。收盘结算时检查：

  - < 140%：推送"追保通知"（警告，不操作）；

  - < 120%：**强制平仓**——按当日收盘价，从市值最大的持仓开始逐只卖出（正常计佣金/印花税），所得现金优先归还负债，直到担保比例 ≥ 130% 或持仓清空；推送强平通知；

  - 强平后若净资产 ≤ 0（资不抵债）→ **爆仓**：状态转 BANKRUPT，游戏提前结束，展示"天台结局"结算页（负债、亏损、存活天数）。

- 融资买入的标的与普通买入一致（不限制标的、不做融券做空）。

## 7. 消息与主力博弈系统（趣味性核心）

### 7.1 主力剧本引擎

每个账户世界中，调度器按概率（约每 20\~40 跳掷骰）为一只**未停牌、无进行中剧本**的股票启动剧本。剧本 = 分阶段定向价格漂移 + 配套消息编排，状态保存在内存。

**剧本一：洗盘吸筹（SHAKEOUT）**

1. *恐慌期*（1\~3 跳）：放出**假利空传闻**（股吧/内幕来源），价格急跌甚至跌停；
2. *磨底期*（5\~15 跳）：低位窄幅震荡，逼散户割肉；
3. *拉升期*（10\~20 跳）：主力强拉，价格创新高；期间或之后公司发布**辟谣公告**（传闻证伪）。

- 玩家博弈：恐慌割肉 = 被洗出局；拿住或抄底 = 获利。

**剧本二：拉高出货（PUMP\_DUMP）**

1. *拉升期*（若干跳）：连续拉涨停（2\~4 板），配套**假利好传闻/内幕**（重组、大单、爆款），股吧狂欢氛围；
2. *出货期*（5\~10 跳）：高位剧烈震荡、涨停反复打开；
3. *崩盘期*（2\~4 跳）：断崖跳水连跌停，同期或事后出现**公司澄清公告/监管问询函**（传闻证伪）。

- 玩家博弈：追高接盘 = 站岗；提前潜伏、高位不贪 = 获利。

**剧本三：尾盘偷袭（TAIL\_WHIP）**

- 下午盘最后 3\~5 跳，价格被突然急拉或急砸 5%\~10%（受涨跌停夹逼），无消息配合，操纵收盘价与次日涨跌停基准。

**剧本四：天地板 / 地天板（SKY\_EARTH）**

- 极端形态：一跳内从涨停砸到跌停（天地板，常伴随午间"窗口指导"类传闻，见 §7.3）或从跌停拉回涨停（地天板）。作为洗盘/出货剧本的高潮事件独立触发。

### 7.2 消息体系：来源分级与真伪生命周期

每条消息带来源标签，发布时**不标注真假**，玩家依据来源可信度自行判断：

| 来源                 | 标签颜色 | 可信度             | 特点                           |
| ------------------ | ---- | --------------- | ---------------------------- |
| 权威公告（公司公告/证监会/交易所） | 红    | 必真              | 滞后——落地时价格 often 已反映；发布即"证实"态 |
| 财经媒体               | 黄    | 高（小概率报道失实，事后辟谣） | 速度快                          |
| 股吧传闻               | 灰    | 低               | 噪声与水军带节奏阵地                   |
| 神秘内幕               | 紫    | 不定              | 提前 30\~60 秒到达，但可能是主力放的饵      |

**真伪三态**：`PENDING`（传闻/未证实）→ 后续揭晓为 `CONFIRMED`（证实）或 `DENIED`（辟谣证伪）；部分传闻保持 PENDING 不了了之。揭晓消息通过 `followup_of` 关联原消息，在数跳后、午休或盘后到达（如"【辟谣】汪洋水产：火山扇贝传闻严重失实"）。

**消息内容库**（化用真实 A 股名梗，硬编码为模板）：

- 公司面：疫苗研发失败连跌停（"关灯吃面"）、养殖海产品"异常失踪"年报巨亏（扇贝跑了）、"海外火山致扇贝涌入"传闻疯传后辟谣、生态故事破灭资金链断裂巨亏（乐视梗）、库存名酒不翼而飞（皇台梗）、财务造假被证监会立案、业绩变脸（三季报预盈→年报巨亏）、重组借壳传闻、董秘暧昧回复、改名蹭热点、跨界收购热门赛道公司连板（爱丽家居梗）、大股东减持、高送转、突发监管问询函。

- 按板块路由到对应股票（如海产梗→汪洋水产、疫苗梗→回春堂、跨界收购→传统行业票）。

### 7.3 全时段消息与隔夜跳空

- **盘中消息**：开盘期间按 §7.1/§7.2 节奏触发事件、传闻、内幕、辟谣。

- **午休消息**（LUNCH\_BREAK 期间）：抽取 0\~2 条午间消息（业绩预告、监管函、"窗口指导"传闻等）。造成的价格冲击以跳空形式作用于**下午盘首跳**（下午 open = 上午收盘价 × (1+冲击)，夹逼涨跌停）；"窗口指导"类传闻可直接引发下午开盘天地板。

- **盘后消息**（SETTLING/CLOSED 期间）：抽取 0\~2 条盘后重磅（立案调查、重组公告、政策发布），冲击幅度写入 `user_stock_state.gap_pct`。

- **隔夜跳空**：次日开盘首跳 `open = prev_close × (1 + gap_pct)`；|gap| ≥ 10% 时开盘即封涨停/跌停（一字板，首跳锁定买/卖方向不可成交）。

- **政策面全市场事件**（scope=MARKET）：降准降息、印花税下调（利好全市场，全部股票正向 gap + 当日漂移偏移）、监管严打异常交易（利空连板股）、外部冲突等。作用于 24 只股票与指数。

### 7.4 停牌核查（小黑屋）

- **异动公告**：股票连续 2 个交易日收涨停，发布《股票交易异常波动公告》（权威消息，纯提示）。

- **停牌核查**：连续 3 个交易日收涨停（或 5 日内 4 板），次日起停牌 1 个游戏交易日：`halted = true`、`halt_until_day = current_day + 1`；停牌期间该股冻结、不可交易；推送"停牌核查"系统通知。

- **复牌**：到达 halt\_until\_day 的开盘时自动复牌；复牌首日大概率补跌（gap −5% \~ −10%，小概率继续涨停——"妖股出关"）。复牌后连板计数清零。

### 7.5 事件触发频率

- 盘中：每 10~~20 跳掷骰触发一次"事件/剧本"（按 90 跳/天节奏，剧本与普通事件合计约 3~~5 次/交易日）；剧本占比约 40%，普通消息事件约 60%；特殊剧本日（§4.4）优先且不占掷骰名额。

- 午休：0~~2 条消息；盘后：0~~2 条消息；政策面全市场事件按纪元编排触发。

- 内幕消息：按剧本编排发放（持仓该股才收到），70% 概率送达。

## 8. 并发控制（核心技术指标）

- **悲观锁（交易主路径）**：交易方法 `@Transactional(rollbackFor = Exception.class)`，事务内：

  1. `SELECT ... FOR UPDATE` 锁定 `sys_user` 账户行；
  2. 再 `SELECT ... FOR UPDATE` 锁定该股票的 `user_position` 行（不存在则插入，重复插入依赖唯一索引兜底后重查加锁）；
  3. 固定加锁顺序：先账户行、后持仓行，防止多事务死锁；
  4. 扣减/增加 balance、更新持仓、写 trade\_record，同事务提交。

- **乐观锁（行情快照）**：`user_stock_state.version`，快照更新失败重试至多 3 次。

- **并发场景**：同一账户多标签页 / 双击 / 脚本重放导致的瞬间并发下单；行情线程与交易线程并发读写。

- 辅助手段：前端按钮点击后置灰防连点；REST 层基础参数校验。

## 9. WebSocket 设计

- 端点：`/ws`，STOMP 子协议；CONNECT 帧携带 JWT（查询参数 token），服务端 ChannelInterceptor 鉴权并建立 Principal。

- 全部为用户私有目的地（点对点，无全局广播）：

| 目的地                         | 内容                                            | 时机              |
| --------------------------- | --------------------------------------------- | --------------- |
| `/user/queue/quotes`        | 本账户 24 只股票最新行情 + 百年指数点位                       | 每 3 秒（开盘中）      |
| `/user/queue/market-state`  | 市场状态、当前交易日、倒计时、午休/收盘/开盘通知                     | 状态切换时           |
| `/user/queue/messages`      | 新消息（公告/媒体/传闻/内幕/辟谣，含来源与三态）                    | 消息产生时（盘中/午休/盘后） |
| `/user/queue/notifications` | 系统通知：停牌/复牌、隔夜跳空、结算评价、称号解锁、纪元切换、熔断、追保/强平/爆仓、通关 | 事件发生时           |
| `/user/queue/trade-result`  | 成交回报（辅助，下单本身 HTTP 同步返回）                       | 成交后             |

## 10. 数据模型

所有金额使用 `DECIMAL(12,2)`，价格 `DECIMAL(10,2)`。

1. **sys\_user**：id、username（唯一索引）、password（BCrypt）、balance、debt（融资负债）、created\_at。
2. **stock\_info**（静态档案，全服共享）：id、stock\_code（唯一）、stock\_name、sector（板块）、base\_price（发行价）。初始化 24 只。
3. **user\_stock\_state**（每账户每只股票的行情状态）：id、user\_id、stock\_id、prev\_close、open\_price、high\_price、low\_price、current\_price、limit\_up\_streak（连板数）、halted（是否停牌）、halt\_until\_day（复牌交易日）、gap\_pct（待应用的隔夜/午间跳空）、version（乐观锁）；唯一索引 (user\_id, stock\_id)。
4. **user\_position**：id、user\_id、stock\_id、shares（总股数）、available\_shares（可卖股数，T+1）、avg\_cost；唯一索引 (user\_id, stock\_id)。
5. **trade\_record**：id、user\_id、stock\_id、trade\_type（BUY/SELL）、price、shares、amount、commission、tax、game\_day、created\_at。
6. **loan\_record**（融资流水）：id、user\_id、loan\_type（BORROW/REPAY/INTEREST/LIQUIDATE）、amount、debt\_after（操作后负债余额）、game\_day、created\_at。
7. **game\_event**（事件与剧本记录）：id、user\_id、stock\_id（可空，政策面为空）、scope（STOCK/MARKET）、script\_type（NONE/SHAKEOUT/PUMP\_DUMP/TAIL\_WHIP/SKY\_EARTH/POLICY/LIMIT\_UP\_ALL/LIMIT\_DOWN\_ALL/CIRCUIT\_BREAKER/SANCTION/CRASH\_WEEK）、event\_type（GOOD/BAD/NEUTRAL）、title、content、impact\_pct、game\_day、created\_at。
8. **user\_message**（消息中心）：id、user\_id、source（AUTHORITY/MEDIA/RUMOR/INSIDER/SYSTEM）、truth\_status（PENDING/CONFIRMED/DENIED）、type（NEWS/TIP/EVENT/NOTIFY）、title、content、stock\_id（可空）、followup\_of（原消息 id，辟谣/证实关联）、is\_read、game\_day、created\_at。
9. **user\_game\_state**（单行/账户）：id、user\_id（唯一）、current\_day、market\_state、tick\_index、index\_value（百年指数昨收/当前快照）、prev\_total\_asset（昨日结算总资产，用于日收益率）、vol\_regime（当日波动率体制 CALM/NORMAL/WILD）、end\_reason（空/NORMAL\_FINISH/BANKRUPT）、end\_day、updated\_at。
10. **user\_title**（称号成就）：id、user\_id、title\_code、title\_name、game\_day（解锁日）、created\_at；唯一索引 (user\_id, title\_code)。
11. **user\_era**（本局纪元时间表，注册时掷出）：id、user\_id、era\_index（1..11）、era\_code、start\_day、end\_day、params\_json（该纪元随机掷出的 μ\_mkt、板块系数字段）；唯一索引 (user\_id, era\_index)。
12. **user\_script\_day**（本局剧本日排期，注册时掷出）：id、user\_id、game\_day、script\_type（LIMIT\_UP\_ALL/LIMIT\_DOWN\_ALL/RESCUE/CIRCUIT\_BREAKER/SANCTION/CRASH\_WEEK）、params\_json（封死比例、目标股、跌停日数等随机参数）；唯一索引 (user\_id, game\_day, script\_type)。

**注册事务内自动播种**：创建 sys\_user（balance=100,000, debt=0）+ user\_game\_state（current\_day=1, market\_state=NOT\_STARTED, tick\_index=0, index\_value=1000, vol\_regime=NORMAL）+ 24 行 user\_stock\_state（current/open/high/low/prev\_close 均 = base\_price）+ **调用世界排期器掷出 11 行 user\_era（边界抖动 + 强度参数）与全部 user\_script\_day（剧本日落点与参数）**。

### 称号一览（结算/成交时检测，解锁推送通知）

- 初入股市：首次成交

- 关灯吃面：单日总资产跌幅 ≥ 5%

- 接盘侠：买入后 2 个交易日内该股跌 ≥ 15%

- 逃顶大师：清仓后 1 个交易日内该股跌停或跌 ≥ 10%

- 抄底能手：跌停附近买入后当日/次日涨停或涨 ≥ 10%

- 股神：连续 5 个交易日跑赢百年指数

- 长线是金：单笔持仓满 5 个交易日且盈利 ≥ 20%

- 割肉专家：累计亏损卖出达 10 次

- 韭菜王：累计总亏损 ≥ 20%

- `POST /api/trade/buy` `{stockId, shares}`、`POST /api/trade/sell` `{stockId, shares}`

- `POST /api/loan/borrow` `{amount}`（融资借款，校验 ≤ 净资产）、`POST /api/loan/repay` `{amount}`（还款）

- `GET  /api/game/result`：终局结算页数据（结局类型、存活天数、总收益率、指数涨幅、段位、强平记录）

- `GET  /api/market/state`：market\_state、current\_day（年/第几天）、当前纪元名称与叙事、tick\_index、阶段倒计时

- `POST /api/market/start`：开始第 1 天 / 下一交易日（幂等）

- `POST /api/market/skip`：跳过当日/下一交易日（快进模拟至收盘并结算），返回收盘总结 DTO（§12.7）；终局态拒绝。

- `GET  /api/market/daily-summary?gameDay={n}`：某日收盘总结数据（默认最近结算日）：日收益率、指数日涨跌幅、资产快照、担保比例、当日要闻列表、T+1 解冻/追保/强平/停牌提示、玩梗评语、当前纪元与明日风险提示。

- `GET  /api/messages`（按来源/三态/已读筛选）、`PUT /api/messages/{id}/read`

## 13. 错误处理

- 业务异常统一 `BusinessException` + `@RestControllerAdvice` 返回标准错误码与文案。

- 明确文案场景：未登录 / token 过期、休市中拒单、非整手、涨停拒买、跌停拒卖、停牌拒单、资金不足、可卖股数不足、股票不存在、重复开盘（幂等返回当前状态）、终局态跳过/交易拒绝、融资额度不足、还款金额超过负债。

- WebSocket 推送失败不影响交易主流程；消息推送失败仅记录日志。
